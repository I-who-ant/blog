# Astro 博客页面与组件开发规范

> 本文约定了在 `seeback-astro` 项目中新增页面、组件与内容的推荐流程，确保目录结构清晰、复用有序。

## 1. 目录结构约定

- `src/pages/`：页面级 `.astro` 文件，负责路由与内容组织，不直接书写重复结构。
- `src/layouts/`：布局组件，目前提供 `MainLayout` 作为全站基础骨架。
- `src/components/`：所有可复用的展示组件必须存放于此目录，例如导航、页脚、列表等。
- `src/content/`：使用 Astro Content Collections 存放 Markdown 文章与数据文件。
- `src/styles/`：全局样式或公共样式文件。

> 约定：**新增组件一律放在 `src/components` 下**，若有子领域（如 `blog/`、`shared/`），可在该目录内再分子文件夹。

## 2. 新增页面流程

1. 在 `src/pages` 下创建对应路由文件，例如 `src/pages/project/index.astro`。
2. 页面内部首选 `MainLayout` 作为外层布局，结构如下：
   ```astro
   ---
   import MainLayout from '../layouts/MainLayout.astro';
   import PageHeader from '../components/PageHeader.astro';
   ---

   <MainLayout>
     <PageHeader title="页面标题" description="简单说明" />
     <!-- 页面主体内容 -->
   </MainLayout>
   ```
3. 若页面需要复用模块（如卡片、列表、统计块），请在 `src/components` 中创建对应组件后导入使用。
4. 页面的业务逻辑（数据获取、排序等）写在 frontmatter 中，UI 逻辑交给组件处理，便于测试与迁移。

## 3. 组件开发规范

- 组件命名采用帕斯卡命名（PascalCase），示例：`PostList.astro`、`FriendList.astro`。
- 若组件需要接收参数，使用 TypeScript 定义 props，并保持默认值：
  ```astro
  ---
  interface Props {
    title: string;
    description?: string;
  }
  const { title, description } = Astro.props as Props;
  ---
  ```
- 组件样式优先复用 `src/styles/base.css`，如需新增全局样式，可在该文件中补充；若仅在组件内部生效，可使用内联 `<style>` 并配合 `:global` 选择器。
- 与布局关联度高的组件（如导航、页脚）保持纯展示，不在内部耦合业务逻辑，数据由布局负责注入。

## 4. 内容与数据维护

- 文章位于 `src/content/posts/`，使用 Markdown 格式，frontmatter 需包含 `title` 与 `date` 字段，可选 `excerpt`、`tags` 等。
- 友链数据位于 `src/content/friends/friends.json`，新增条目需提供 `name` 与合法的 `url`。
- 新文章或数据更新后执行 `npm run build` 可在本地验证渲染效果。

## 5. 构建与部署

- 开发模式：`npm install && npm run dev`。
- 生产构建：`npm run build`，输出静态文件位于 `dist/`。
- 静态部署时，仅需上传 `dist/` 内容至任意静态托管（GitHub Pages、Vercel、Netlify 等）。
- CI/CD 建议：在推送至主分支后触发构建并自动发布，以保证内容更新可追溯。

## 6. 质量检查清单

- [ ] 新增组件是否放置在 `src/components` 并编写类型定义。
- [ ] 页面是否复用 `PageHeader` 等基础组件，避免重复结构。
- [ ] 样式命名是否符合语义化，存在复用时是否抽取到公共样式。
- [ ] 内容更新后是否执行本地构建并预览页面。

遵循以上规范可以在保证交付效率的同时，保持 Astro 博客项目的可维护性与一致性。
