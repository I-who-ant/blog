# Astro 博客页面与组件开发规范

> 本文约定了在 `seeback-astro` 项目中新增页面、组件与内容的推荐流程，保持目录结构清晰、写作体验顺畅。除非另有说明，命令默认使用 `npm`。

## 1. 目录结构约定

- `src/pages/`：页面级 `.astro` 文件，负责路由与内容组织，不直接书写重复结构。
- `src/layouts/`：布局组件，目前提供 `MainLayout` 作为全站基础骨架。
- `src/components/`：所有可复用的展示组件必须存放于此目录，例如导航、页脚、列表等。
- `src/content/`：使用 Astro Content Collections 存放 Markdown 文章与数据文件。
- `src/styles/`：全局样式或公共样式文件。

> 约定：**新增组件一律放在 `src/components` 下**，若有子领域（如 `blog/`、`shared/`），可在该目录内再分子文件夹。

## 2. 新增页面流程

1. 在 `src/pages` 下创建对应路由文件，例如 `src/pages/project/index.astro`。
2. 页面内部首选 `MainLayout` 作为外层布局，结构如下：
   ```astro
   ---
   import MainLayout from '../layouts/MainLayout.astro';
   import PageHeader from '../components/PageHeader.astro';
   ---

   <MainLayout>
     <PageHeader title="页面标题" description="简单说明" />
     <!-- 页面主体内容 -->
   </MainLayout>
   ```
3. 若页面需要复用模块（如卡片、列表、统计块），请在 `src/components` 中创建对应组件后导入使用。
4. 页面的业务逻辑（数据获取、排序等）写在 frontmatter 中，UI 逻辑交给组件处理，便于测试与迁移。
5. 页面涉及的样式尽量复用 `src/styles/base.css` 中已有的语义化 class；确需新增全局变量时，请在该文件顶部的 `:root` 或 `html.theme-light` / `html.theme-dark` 下补充。

## 3. 组件开发规范

- 组件命名采用帕斯卡命名（PascalCase），示例：`PostList.astro`、`FriendList.astro`。
- 若组件需要接收参数，使用 TypeScript 定义 props，并保持默认值：
  ```astro
  ---
  interface Props {
    title: string;
    description?: string;
  }
  const { title, description } = Astro.props as Props;
  ---
  ```
- 组件样式优先复用 `src/styles/base.css`，如需新增全局样式，可在该文件中补充；若仅在组件内部生效，可使用内联 `<style>` 并配合 `:global` 选择器。
- 与布局关联度高的组件（如导航、页脚）保持纯展示，不在内部耦合业务逻辑，数据由布局负责注入。

## 4. 内容与数据维护

- 文章位于 `src/content/posts/`，**默认使用 `.md`**。frontmatter 至少包含：
  ```yaml
  ---
  title: '文章标题'
  date:  '2025-10-08T21:00:00+08:00'   # 推荐写到时区，便于排序
  excerpt: '选填摘要'
  tags: [收获, 日常]                    # 可选
  ---
  ```
  - `date` 会在集合层自动转换为 `Date` 对象，以保证同一天多篇文章可以按时间排序。
  - 如果暂时不需要增强语法，请继续写 `.md`；需要引入 Astro 组件或 Markdoc 标签时，可将单篇文章改名为 `.mdx` / `.mdoc`。
- Markdown 写作建议：
  - 水平分隔线使用单独一行的 `---`，并在上下各留一个空行。
  - 代码块使用 fenced 语法（```` ```tsx ... ``` ````），Shiki 会自动高亮；代码行过长会出现横向滚动条，不需要手工断行。
  - 引用 `>` 会自动带有主题化的左侧边框，无需额外样式。
- 友链数据位于 `src/content/friends/friends.json`，新增条目需提供 `name` 与合法的 `url`。
- 新文章或数据更新后，可执行：
  - `npm run dev` 本地预览；
  - `npm run build` 静态构建，确保生产环境渲染无误；
  - `npm run astro -- sync`（或 `npx astro sync`）在 schema 变更后重新生成类型文件。

## 5. 构建与部署

- 初始化项目：`npm install`。
- 开发模式：`npm run dev`。
- 生产构建：`npm run build`，输出静态文件位于 `dist/`，可直接部署至任意静态托管（GitHub Pages、Vercel、Netlify 等）。
- CI/CD 建议：推送主分支后触发 `npm run build` 并自动发布静态产物。

## 6. 质量检查清单

- [ ] 新增组件是否放置在 `src/components/`，并声明了 props 类型。
- [ ] 页面是否复用 `MainLayout` + `PageHeader` 等基础结构，避免重复代码。
- [ ] 新 CSS 是否按主题变量整理，或仅在组件内局部生效。
- [ ] 文章 frontmatter 是否包含 `title`、`date`，日期是否采用 ISO 格式。
- [ ] 新内容写入后是否运行 `npm run build` / `npx astro sync` 进行验证。

遵循以上规范可以在保证交付效率的同时，保持 Astro 博客项目的可维护性与一致性。
